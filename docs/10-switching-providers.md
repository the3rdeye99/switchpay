# 10. Switching providers

This is the reason Switchpay exists — switching between Paystack and
Flutterwave is changing **one line** in your environment.

## From Paystack to Flutterwave

```diff
- SWITCHPAY_PROVIDER=paystack
+ SWITCHPAY_PROVIDER=flutterwave
```

Now swap the key and webhook secret values for Flutterwave's:

```bash
SWITCHPAY_PROVIDER=flutterwave
SWITCHPAY_SECRET_KEY=FLWSECK_test_xxx
NEXT_PUBLIC_SWITCHPAY_PUBLIC_KEY=FLWPUBK_test_xxx
SWITCHPAY_WEBHOOK_SECRET=flutterwave_dashboard_hash
```

And in your provider dashboard:

1. Point Flutterwave's webhook URL at `/api/switchpay/webhook`.
2. Set your `verif-hash` to the value of `SWITCHPAY_WEBHOOK_SECRET`.

## What does NOT change

Everything else stays exactly the same:

- Your `<PayButton />` / `useSwitchpay()` code
- Your route handler files
- Your `onPaymentSuccess` / `onPaymentFailed` callbacks
- Your webhook URL
- Your error handling

Switchpay normalizes both providers behind one interface, so no provider
details leak into your code.

## Caveats to be aware of

- **Key formats differ.** Paystack uses lowercase `sk_`/`pk_` prefixes;
  Flutterwave uses `FLWSECK`/`FLWPUBK`. `loadConfig()` validates the prefix
  against the declared provider, so a mismatch fails fast with `INVALID_KEY`.
- **References are provider-generated.** Paystack returns its own reference;
  Flutterwave references are generated by Switchpay. Store the reference
  generically (just a string) and don't rely on the specific format.
- **Webhook secrets differ.** Paystack's webhook secret *is* its secret key;
  Flutterwave's is a separate hash you configure. Update
  `SWITCHPAY_WEBHOOK_SECRET` accordingly.
- **Currency conversion differs internally.** Paystack transacts in minor
  units; Flutterwave in major units. Switchpay converts for you — you always
  work in major units. See [12. Currency & amounts](12-currency.md).

## Going back

Revert `SWITCHPAY_PROVIDER` and the key values. No code changes needed.
